1. 发生了什么

北京时间 10 月 18 日晚，VAST 发布并开源 EdenLive（量子位 19:49 首发报道；Hugging Face 的 Adina Yakup 20:42 在 X 转发）。它是 VAST 世界模型研究项目 Project Eden 的阶段性成果。VAST 就是做 3D 生成平台 Tripo 的那家公司（中文名「三启万物」）。这次放出的东西有 5 样：

  • 5B 和 14B 两档模型权重，每档都有「整段一起生成」和「少步分块自回归（实时用）」两种版本，合计约 210GB；
  • 实时流式推理代码，通过 WebRTC 推流；
  • 技术报告；
  • 「Game Prototype Turbo」技能：一句话生成一个能玩的低模游戏；
  • 一个前端工作台，可以把「一句话 → 低模游戏 → EdenLive 实时渲染」整条链路跑通。

2. 产品介绍

我逐帧看了官方 96 秒演示视频，还读了技术报告。它的分工是这样的：

  • 上游程序（管「发生了什么」）：游戏引擎，或者编程 Agent 写出来的小游戏。负责规则、碰撞、血量和世界状态，只输出一段很粗的参考视频（灰盒、像素风、方块人）。
  • EdenLive（管「长什么样」）：吃三样输入。参考视频决定布局、镜头和运动；目标首帧决定整体外观和画风；提示词补充风格和细节。它把这三样合起来，实时画出精细画面。参考视频先由一个微调过的 DINOv3 视觉编码器转成特征，再喂给视频模型。
  • 底座：5B 基于阿里 Wan2.2-TI2V-5B（720p），14B 基于 Wan2.1-I2V-14B（480p）。
  • 演示里的用法：岩浆闯关（用冷冻枪造落脚点）、街头双人对打、矿洞、潜艇抓取、城市空战、雪地铲车、实拍街景转梵高画风、第一人称人手换成机械手（做具身数据增强）。

3. 导致什么影响

对行业：Matrix-Game 4.0（10-15）、NVIDIA StreamRender-H3、EdenLive（10-18）都把「世界怎么运行」交给代码，把「世界长什么样」交给模型。这条路线的好处是规则可控、状态不会忘；代价是每个世界都得先有一个能跑的程序。EdenLive 把渲染器做成了通用件，同一个模型接不同游戏和不同画风，比 Matrix-Game 4.0 的「一个游戏一个渲染模型」前进了一步。

对开源生态：两家国产公司 4 天内先后开源，权重、推理代码、技术报告都放了，任何团队都可以在同样的硬件上复现，再拿来对比。

竞品对比

谁做法和硬件差在哪（有证据）
EdenLive（VAST）通用渲染器：任意参考视频 + 首帧 + 提示词；5B 单卡720p；H100 上 29.8 帧/秒、首帧 1.16 秒（自测）；Apache-2.0 为主，工作台首帧组件非商用。
Matrix-Game 4.0（昆仑万维，10-16 期报过）引擎 + 每个游戏单独训的渲染模型；单张 RTX 5090480p / 60 帧，按键到出画 112 毫秒（自测）；地图和动作固定。EdenLive 的报告没有和它比，两家的延迟口径也不同，不能直接排座次。
StreamRender-H3（NVIDIA）引擎语义图 + 视频模型；8 张 GPUEdenLive 报告表 2 在同一份 30 秒输入上测得 2.56 帧/秒（8 张 H100，1344×768），远达不到实时。这是对手测的，不是 NVIDIA 自报。
AgentGarten大模型写代码生成世界 + 渲染同一张表测得 36.1 帧/秒（832×480，1 张 H100），比 EdenLive 5B 同分辨率慢一半；长时对比里 EdenLive 14B 多数指标领先（EdenLive 自评）。
Odyssey-3 / Genie 3纯模型，不需要上游程序能一句话直接生成新世界，但规则不可编程、状态靠模型自己记；都不开源。
和我们的关系：4 个值得问算法同学的问题
  • 白模直接能接：EdenLive 的输入就是灰盒代理视频。我们的白模轨迹可以直接喂给它，和我们自己的模型并排比：同一段白模，谁的画面更稳、更像、更跟手？
  • 路线叙事：两家国产开源都选了「引擎管状态」。我们是纯模型，用 WASD + IJKL + 文字控制。我们的卖点是「不需要每个世界先写一个程序」，这一点要讲清楚；同时也要回答「状态会不会忘、规则能不能保证」。
  • 延迟要比对口径：对外比较时，除了帧率，还要报首帧延迟和块间 P95。EdenLive 在 H100 上 720p 首帧约 1.2 秒，Matrix-Game 自报 112 毫秒，我们自己的数字是多少？
  • 数据：EdenLive 的配对数据是把实拍视频和游戏渲染画面「从精到粗」退化得到的。这和 Matrix-Game 用 1,712 小时 UE5 配对数据是两种做法，我们的数据产线可以参考。

2. 产品介绍

  • 两层结构：上层 Murea-Mind 是 Agent，像编剧兼导演。它维护一本「世界账本」，记录角色、物品、地点、剧情进度；读当前状态和用户指令，规划下一个事件，生成后回看画面，再把变化写回账本。下层 Murea-Pro / Murea-Fast 负责同时生成画面和声音（含台词）。
  • 多参考：人物、动物、物品、场景各给一张参考图，模型按编号认人，所以十几段视频之后角色和道具还是同一个。
  • 玩法：每轮一段约 5 秒视频；可以撤销、开分支；2–4 人合作模式下，每个玩家带一个角色，每轮合成一段。
  • 速度：开源的 Fast 版在 4 张 H20 上生成 5 秒片段约 16 秒（单张 H20 约 45 秒）。没发布的 Pro 版，在 8 张 H20 上约 7 秒，在 RTX PRO 6000 上约 3.6 秒（机器之心引用报告）。
  • 底座：Murea-Fast 是 Lightricks 的 LTX-2.5 的衍生模型，跑起来还要拉 LTX-2.5 的全套组件，外加一个 Gemini / OpenAI 兼容 / 通义的 API key 给 Agent 用。
