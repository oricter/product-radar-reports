结论：这是本期和我们工作最近的一条，因为它解决的正是数据产线的问题：海量视频怎么自动变成「切好段、写好指令、标好质量」的训练数据。英伟达把训练 GR00T 时内部用的标注流水线整套开源，说明这类「标注模型」已经成了具身和世界模型团队的标配基础设施。

2. 产品介绍

我逐帧看了官方 67 秒视频，读了论文和模型卡。拆开是一条三段流水线：

  • 第一步 · 切段（Flora-TempSeg 9B）：把一段长视频切成一个个动作片段，比如「拿起马克杯」「放进盒子」。
  • 第二步 · 写指令（Flora-Captioner 27B）：给每段写带起止时间的文字指令。机器人视频和人手视频都能写（官方视频里有人弹吉他、双臂机器人插花、灵巧手开信箱的例子）。
  • 第三步 · 打分（Flora-Rewarder 27B），三种输出：
    • 整段结果打 1–5 分（做成没有）；
    • 每 0.5 秒一个过程标签：正常 / 做得差 / 失败，并写原因；
    • 按任务自动生成评分细则（rubric）再逐条打分，比如「把绿色马克笔从杯子里拿出来」拆成几步分别检查。
  • 用途：标好的数据用来训练机器人策略模型；打分结果可以当强化学习的奖励，也可以用来筛掉烂数据。
  • 硬件门槛：27B 模型在 X 上有人问「要 32GB 显存？」，按参数量估计单卡至少需要 32GB 以上，或者量化后跑。

3. 导致什么影响

对行业：机器人和世界模型的数据瓶颈正在从「拍视频」挪到「标视频、筛视频」。之前大家要么雇人标（贵、慢），要么调 GPT / Gemini 的 API 标（每小时视频几十美元，而且标不出失败）。英伟达把一套专门训练过的小模型开源，把成本压到 1 美元以内。这会让更多学术团队和小公司有能力做大规模数据标注，也给闭源 API 标注定了一个价格参照。

对英伟达自己：开源标注工具能让更多人产出 GR00T 格式的数据、在英伟达的卡上跑，是在给自家机器人生态铺路。和 Cosmos 世界模型、GR00T 模型一起，英伟达在具身 AI 上「模型 + 数据 + 工具」全都开放了。

和我们的关系：3 个值得问的问题
  • 标注：我们的视频片段要配文字指令（WASD / IJKL 之外的文字控制），Flora-Captioner 这种「带时间戳的指令」正好是这个格式。能不能用同样的思路自动写？
  • 质检：Flora-Rewarder 的「每 0.5 秒标正常 / 做得差 / 失败 + 原因」，换到我们的场景可以是「画面漂移 / 穿模 / 指令没执行」。能不能训一个类似的质检模型来筛数据？
  • 许可：直接用 Flora 只能做研究。如果试下来好用，路线是参考论文在 Qwen3.5 上自己训一个（Flora 本身就是 Qwen3.5 加 LoRA），需要先估一下要多少标注数据。

2. 产品介绍

  • 输入：最多 12 个参考，其中图片最多 9 张、视频最多 3 段、音频最多 3 段，再加一句文字提示。
  • 输出：5–15 秒视频，24 帧/秒，1344×768，带立体声（对白、音效）。
  • 怎么变快：原版每次生成要跑 50 次 Transformer，蒸馏后只跑 8 次。方法是 PDD（渐进式蒸馏）加 DMD（分布匹配蒸馏）。
  • 官方速度：8 张 GB200 上测了 27 种组合，延迟降低 5.6–11.9 倍。例子：1 张图生成 5 秒视频，从 35.44 秒降到 5.67 秒。注意测的是「lossless」策略，不是「exact」。
  • 本地跑：RTX 5090 默认出 480p。X 上一位日本用户用 RTX 5080 生成 5 秒 720p 带人声的视频，约 1.5 分钟。

3. 导致什么影响

对行业：「多参考 + 音视频一起生成」是今年视频生成的主战场，Seedance 2.5、可灵 4.0 都靠它拉开差距。MiniMax 先把 H3 开放出来，FastVideo 再把它压到消费级显卡能跑，意味着做短剧、动画、虚拟人的小团队可以不付 API 费、在本地批量生成。MiniMax 官方账号也在回复里说「迫不及待想看训练代码」，看起来是乐见其成。

对实时生成：50 步到 8 步是「视频模型变实时」的关键一步。蒸馏方法和训练代码都公开了，别的团队可以照着做。

和我们的关系
  • 实时推理参考：PDD + DMD 把 50 步压到 8 步，训练成本约 7,800 GPU 小时。值得让算法同学看看能不能用在我们的模型上。
  • 数据合成：理论上可以用它按参考图批量生成角色一致的片段，但要先确认 MiniMax 社区协议对生成数据用于训练的限制。

判断：开源视频圈小热，收藏和点赞差不多（309 对 344），说明很多人准备自己跑。好评集中在「本地真的能用」，质疑集中在「对比对象和质量评测」。

  • 好评：有用户做了 ComfyUI 工作流和低显存的 GGUF 版本，评价「快得离谱，也准」（@realrebelai）；一位日本用户在 RTX 5080 上约 1.5 分钟出了 5 秒 720p 带人声的视频。

  • 门槛：「没有 5090，16GB 的卡用 NVFP4 也带不动」（@xclearcast）。

③ humans& 发布首个协作模型 Ampersand v0.1（北京时间 10-21 06:37）：专门在群聊里帮一群人协作、会判断何时闭嘴，扣掉打扰成本后和 Fable 5.1 打平

结论：和世界模型无关，但它是一个值得记住的Agent 产品形态：AI 不是一对一助手，而是坐在群里的成员，每条消息后先决定「说话还是不说」。这家公司种子轮就拿了 4.8 亿美元，第一个模型却是在开源的 GLM 5.3 上做后训练，说明他们押的是「训练目标和评测」，不是底座。
  • 领先底座很多，但没甩开前沿模型：自家「长期协作」评测 12.94 对 GLM 5.3 的 9.89；扣掉打扰成本后，Anthropic 的 Fable 5.1 是 12.95，基本打平，博客自己也承认 Ampersand「提醒和指导」的成本更高。
  • 代价：SWE-bench Pro 从 84.3% 降到 82.4%；模型卡说它比前沿模型更容易被提示词注入，网络安全知识分也升高了。
  • 评测靠模拟用户：多位用户质疑「模拟器好不等于真团队好」。

2. 产品介绍

  • 底座：智谱 GLM 5.3（744B MoE，约 40B 激活参数，100 万上下文）。
  • 怎么在群里工作：每条新消息后，模型选一个工具：send_message（说话）或 pass（不说）。
  • 怎么训的：用名为 Persimmon 的用户模拟器，模拟一群人连续几个月的协作，再用他们自己的离线强化学习算法 CORO 训练。
  • 博客里的例子：Sam 前面提过「周五我不在」，后来 Maya 提议周五排练，Ampersand 主动插话提醒「Sam 周五不在」。其他时候它保持沉默。

3. 导致什么影响

对 Agent 产品：现在主流 AI 助手都是一对一的；飞书、Slack 里的群聊机器人基本是「被 @ 才回答」。Ampersand 的不同在于专门训练「什么时候该主动说、什么时候该闭嘴」，并把它做成可量化的评测（打扰成本）。如果这条路走通，群聊里的 AI 会从「工具」变成「成员」。
