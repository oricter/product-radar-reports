🎯 怎么评分

总分公式

每项小指标先算出每题的分，再对所有适用的题取平均并换成 0–100 分 → 每个维度取它下面小指标的平均 → 5 个维度等权平均就是总分。没有其他加权。

Navi 和 Full 的区别

Navi 只算 158 道导航题，「交互」维度只看导航分。Full 算全部 289 题，「交互」是导航、事件、角色动作、视角切换四项的平均。

维度（各占 1/5）小指标谁来打分
画面质量美感、成像清晰、闪烁、动态程度、运动平滑、HPSv3 人类偏好分（按百分位归一化）VBench 的打分模型、HPSv3 奖励模型
设定遵循场景遵循：开头画面里的东西有没有保持住，画面外描述的东西后来有没有出现。主体遵循：角色外观和动作风格对不对豆包 VLM（doubao-seed-2.0-lite）
交互遵循① 导航：用 MegaSaM 从视频反推相机轨迹，跟按键算出的标准轨迹比。准确度 = 1 − 平均误差（nATE），一致性 = 重复同一个键时轨迹像不像，导航分 = 两者平均。只看方向对不对，不看走多快多远。
② 事件和③ 角色动作：每轮检查 5 项（画面有变化、事件发生了、做完了、细节对、没有怪异），满足几项得几分，满分 5 分，再换成百分制。
④ 视角切换：每轮检查 3 项（看得到切换过程、切到了对的视角类型、新视角构图合规），三项全过才算成功，得分是成功轮的比例		导航用 MegaSaM，其余用豆包 VLM
一致性背景一致、往返回到原位时像不像原画面（加一个防止原地不动刷分的门控版本）、视角稳定、没有突然跳切、几何一致、光度一致、主体一致CLIP、DreamSim、TransNetV2、SAM2、Depth Anything 3、DINOv2
物理因果合理性：先整体看物理和因果有没有问题，再按题看流体、碰撞、风、反射、人体动作等相关项，每项 0–3 分。视觉合理性：有没有变形、穿模豆包 VLM；视觉合理性用官方微调的 Qwen3-VL-30B

依据：论文第 4 节和附录 C，官方代码 main.py 里的 generate_report 和 tools/add_three_models_homepage.py（注释写明「Overall = mean(5 dims)」）。哪些指标算哪道题，由每题 JSON 里的 metric_list 决定。

1. 题目长什么样

  • 每题 = 1 张首帧图 + 场景/角色/视角的英文描述 + 2–9 轮操作
  • 每轮默认 4 秒（见上面的时长说明），按住一个键（或组合键）或执行一句文字
  • 首帧图多数 1376×768；官方示例视频 24fps；分辨率没硬性要求
  • 所有轮拼成一个视频：case_<id>_combined.mp4

4. 一步步怎么打

  1. 拿题：克隆上面的私有仓库，或官方：hf download meituan-longcat/WBench --repo-type dataset --local-dir data/ --exclude "splits/*"
  2. 拿评测代码：git clone --recursive https://github.com/meituan-longcat/WBench.git，把题目放进 WBench/data/
  3. 写适配器：继承官方 ActionConditionedModel，实现 generate_with_actions(image, actions, video_length)，返回 BGR 帧列表。仓库里 adapter/wasd_ijkl_adapter.py 已写好按键转换。
  4. 跑 158 题：python generate.py --model our_model --cases <navi_ids.txt 里的 id> → work_dirs/our_model/videos/case_<id>_combined.mp4
  5. 写 turns.json：每题每轮的起始帧 + 结尾帧（例 [0,96,192,288,384]）。不写就按平均切，第一轮更长的话会丢分。
  6. 自测（可选）：要 NVIDIA GPU（Linux/CUDA，Mac 跑不了）+ 火山引擎豆包 API key：bash tools/install.sh wbench-main cu124 → python main.py --model our_model，再在 wbench-vp 环境跑 tools/run_visual_plausibility.py
  7. 打包：our_model/ 里放 meta.json（type 填 action）+ report.json（自测才有）+ turns.json + videos/
  8. 上传：videos 放 HuggingFace 数据集（官方首选）/ Google Drive / 百度网盘 / OneDrive
  9. 发邮件给 kaining.ying.cv@gmail.com 和 rensiyu07@meituan.com，标题 [WBench Submission] 模型名，正文写模型名、类型、tags、机构、一句话介绍、自测(A)还是官方测(B)；附 meta.json

5. 两种提交方式

A. 自己测（官方默认）

交分数 + 视频。快，官方抽查几题复核就上榜。需要 GPU + 豆包 API。

B. 官方帮测

只交视频。不用算力，但要排队批量处理。

6. 规则要点

  • 必须正好覆盖 158 个 Navi 题，多一个少一个都会被退回（官方先跑 validate_submission.py）
  • tags 最多 4 个，每个 1–16 字符；不能写机构名、开源/API、排名。写 realtime 要在邮件里给硬件、分辨率、速度
  • 人工审核，官方没写要多久

7. 还不知道的

  • 按键模型能不能另外用文字模式交 Full 榜（导航轮用按键、其余用文字）——官方写 Full 只收文字模型，但榜上有相机模型，建议邮件问
  • 审核周期、视频分辨率/fps 下限：官方没写
  • Navi 里 9 道混文字的题，按键模型官方默认给「不动」；我们用文字指令是否允许，没写
